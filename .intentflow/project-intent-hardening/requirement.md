# 需求文档：project-intent-hardening

## 项目意图
`intent-flow_project_intent` 工具投射 @intent 注释时，对文本中的注释特殊序列（`*/`、行首 `@`）自动转义，提取侧对称还原，杜绝投射后产生语法错误或意图文本静默截断。

## 功能清单
1. **投射侧转义**：`generateIntentBlock` 对 intent 文本做注释安全转义
2. **提取侧还原**：`extractIntentFromLines` 对转义序列对称还原，闭环 100% 一致
3. **测试锁定**：词法安全 + 还原一致 + 既有测试不回归

## 核心功能

### 核心功能1：投射侧转义
- **能力**：系统能够在生成 @intent 注释块时，按注释风格自动转义文本中的特殊序列
  - 块注释语言（TS/Java/Go/CSS 等）：`*/` → `*\/`（防终止符提前闭合，消除 TS1127/TS1109）
  - 所有注释语言（块/行/井号）：行首 `@` → `\@`（防被 IntentExtractor 误判为下一个标签而截断）
- **业务价值**：投射含特殊字符的意图文本不再产生语法错误代码、不再静默丢失文本

### 核心功能2：提取侧还原
- **能力**：系统能够在提取 @intent 文本时，将转义序列还原为原文（`*\/` → `*/`、`\@` → `@`）
- **业务价值**：投射→提取闭环后意图文本与用户输入 100% 一致，下游（意图依赖树、残留检查）读到的是原文

### 核心功能3：测试锁定
- **能力**：测试覆盖三种断言——(a) 转义后文件无语法错误（tsc 解析）；(b) 提取文本与原文一致；(c) 既有 481 行测试不回归
- **业务价值**：行为锁定，防后续改动重新踩坑

## 业务规则

### 块注释终止符转义
- **场景**：目标语言使用块注释（`/** */`），且 intent 文本含 `*/` 序列
- **行为**：文本中所有 `*/` 替换为 `*\/`（`\/` 不是终止序列，注释安全闭合）
- **异常处理**：替换是确定性全量替换，无异常分支

### 标签前缀转义
- **场景**：intent 文本某行行首为 `@`（如 `@param x`、`@see foo`），任意注释风格
- **行为**：该行行首 `@` 替换为 `\@`，使提取器不再将其识别为标签边界
- **异常处理**：无；统一规则覆盖 `@intentx` 等非标准标签前缀（`@intent` 本身天然不触发截断，无需特殊处理）

### 提取侧对称还原
- **场景**：`extractIntentFromLines` 提取到转义序列
- **行为**：`*\/` → `*/`、`\@` → `@`，与投射侧对称
- **异常处理**：文本字面天然含 `*\/`/`\@`（罕见）会被还原，接受为已知行为，测试锁定现状

### 场景范围
- **场景**：无注释语法文件（.md/.yaml/.json）走裸文本通道，不做转义（无词法风险）
- **行为**：仅注释通道转义；提取侧还原规则统一适用
- **异常处理**：无

## 预设测试

### 前置条件
- 项目可运行 vitest（`ProjectIntentUseCase.test.ts` 既有 481 行测试全绿为基线）

### 测试步骤

1. **投射含 `*/` 的意图到 .ts 文件**：调用 `generateIntentBlock('x.ts', '支持 /** */ 注释')`
   **预期结果**：生成的注释块含 `*\/` 而非裸 `*/`；用 tsc 解析生成内容无 TS1127/TS1109

2. **投射→提取闭环**：上述生成块经 `extractIntentFromLines` 提取
   **预期结果**：提取文本为 `支持 /** */ 注释`，与原文一致

3. **投射含 `@param` 开头行的意图**：`generateIntentBlock('x.ts', '第一行\n@param x 参数\n第三行')`
   **预期结果**：提取完整文本 `第一行 @param x 参数 第三行`，不截断为仅第一行

4. **行注释语言场景**：`generateIntentBlock('x.py', '第一行\n@param x')`
   **预期结果**：生成 `# @intent` + `# 第一行` + `# \@param x`；提取还原完整

5. **既有测试回归**：运行 `npx vitest run ProjectIntentUseCase`
   **预期结果**：全部通过

### 异常场景

- **文本字面含 `*\/`**：投射不转义（非 `*/`），提取时被还原为 `*/` → 文本与原文不一致。接受为已知行为（发生率极低），测试锁定现状
- **多行意图文本**：按行拆分逐行转义，空行生成 ` * ` 不触发任何转义/截断

## 边界收束

**此时必做**：
- 块注释 `*/` 转义（核心缺陷，已复现 TS1127/TS1109）
- 行首 `@` 转义（已实测静默截断丢数据）
- 提取侧对称还原（闭环一致性的前提）
- 测试锁定（词法安全 + 还原一致 + 回归）

**此时不做**：
- grep 残留检查假阳性 — 使用技巧记录（精确路径模式复查），不涉及工具代码
- 提取器标签边界语义重构（放宽"遇 @tag 停止"）— 边界是 IntentFlow 注释体系的有意设计，改动风险大；当前以投射侧转义规避，若未来出现跨块粘连需求再评估
- 转义开关/可配置项 — 最小实现，无使用场景
