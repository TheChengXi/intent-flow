# 需求文档：未使用代码清理（unused-code-cleanup）

## 项目意图

开启 TypeScript 的 `noUnusedLocals` + `noUnusedParameters` 编译选项，清理由此暴露的 29 个存量未使用代码（19 个文件），使"未使用代码"进入编译期拦截，杜绝死代码继续积累。

## 功能清单

1. **编译选项开启**：tsconfig.json 追加 `noUnusedLocals: true` + `noUnusedParameters: true`
2. **存量清理**：清除 29 个错误（TS6133 未读取 × 27 + TS6196 未使用 × 2）
3. **验证与回归**：tsc 零错误（含新选项）+ vitest 29/29 + CLI/pi 冒烟

## 核心功能

### 核心功能1：编译选项开启
- **能力**：系统能够在编译期拦截未使用的局部变量、import、参数与类型导入
- **业务价值**：与 compile-error-repair 的"tsc 零错误"基线叠加，死代码从"人肉清理"变为"编译期强制"

### 核心功能2：存量未使用代码清理
- **能力**：系统能够清理 29 处未使用代码（19 个文件），覆盖三种形态：未使用 import（约 9 处）、未使用局部变量（约 18 处）、未使用参数（约 2 处）
- **业务价值**：消除误导性代码，后续改动可安全依赖编译期检查

### 核心功能3：回归验证
- **能力**：系统能够在清理后保持 tsc 零错误、测试 29/29、CLI/pi 冒烟正常
- **业务价值**：证明清理零行为影响

## 业务规则

### 未使用 import 删除
- **场景**：import 声明从未被读取
- **行为**：直接删除该 import 行（含 `import type`）；删除后若文件无任何 import，保留空文件结构
- **异常处理**：import 名字与局部变量重名（被遮蔽使用）→ 不删，人工确认

### 未使用局部变量删除（副作用逐个确认）
- **场景**：局部变量声明后从未被读取
- **行为**：查看初始化表达式——无副作用（纯值/字面量/构造无副作用的类型转换）→ 删除整行；有副作用（函数调用、属性访问、new 表达式）→ 保留调用表达式（改为裸表达式语句 `expr;`）或与用户确认
- **异常处理**：不确定副作用 → 停下询问，不擅自删

### 未使用参数策略
- **场景**：函数参数从未被读取
- **行为**：若参数属于接口/抽象签名的一部分（实现类、回调、重写方法）→ 参数名前加 `_` 前缀保留（如 `_agent`）；若参数为普通函数私有签名 → 直接删除参数
- **异常处理**：参数被解构使用部分字段（如 `({ a, b })` 只用 a）→ 解构中删除未用字段而非整个参数

### 验证判据
- **场景**：清理完成后
- **行为**：`npx tsc --noEmit`（tsconfig 含新选项）零错误；`npm test` 29/29；CLI 冒烟正常
- **异常处理**：任何验证失败 → 回滚对应文件改动，单独分析

## 预设测试

> 从用户视角可执行的测试步骤，验证功能是否符合预期。

### 前置条件
- Node.js + 依赖已安装（compile-error-repair 后基线：tsc 零错误、vitest 29/29）

### 测试步骤

1. **[编译检查]**：运行 `npx tsc --noEmit`
   **预期结果**：零错误（tsconfig 已含 noUnusedLocals/noUnusedParameters）

2. **[选项生效验证]**：临时在任意文件加 `const unused = 1;` 后运行 tsc
   **预期结果**：报 TS6133（证明选项生效）；移除后恢复零错误

3. **[单元测试]**：运行 `npm test`
   **预期结果**：29/29 通过（证明清理零行为影响）

4. **[CLI 冒烟]**：运行 `npx tsx src/adapter/cli/index.ts check-file-size src/data/entities/index.ts`
   **预期结果**：正常输出

5. **[pi 冒烟]**：运行 `npx tsx -e "import('@earendil-works/pi-tui').then(m => console.log('ok', Object.keys(m).length))"`
   **预期结果**：正常输出（pi 相关改动最多的 adapter 未破坏）

### 异常场景

- **[副作用误删]**：清理后 CLI/测试行为变化 → 恢复该行，确认副作用后以裸表达式保留
- **[参数签名破坏]**：删除参数导致接口实现不匹配 → 改用下划线前缀方案
- **[选项误伤]**：开启选项后其他文件新增报错（如第三方类型）→ 检查是否 skipLibCheck 覆盖范围外的问题，单独处理

## 边界收束

**此时必做**：
- tsconfig 开启 2 个选项
- 清理 29 个存量错误（19 个文件）
- 回归验证（tsc + vitest + 冒烟）

**此时不做**：
- 其他 unused 相关选项（noUnusedLabels、noUncheckedIndexedAccess 等）— 超出本 feature 对象，需单独评估
- 未使用代码的"重构性清理"（如提取公共逻辑、合并重复代码）— 本次只做删除型清理，重构另立 feature
- webview/src 内的未使用代码 — 其不在根 tsc 编译域（compile-error-repair 隔离），由 webview 自身构建链管理
- 第三方类型定义（node_modules .d.ts）中的未使用项 — skipLibCheck 已覆盖
