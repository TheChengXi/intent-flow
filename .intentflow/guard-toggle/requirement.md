# 需求文档：guard-toggle（守卫开关）

## 项目意图

给 ToolAccessGuard 增加一个用户运行时可控的全局开关（auto 模式）：关闭后 edit/write/bash 不再弹确认框直接放行，状态持久化到项目根目录，重启保持。

## 功能清单

1. **`/guard-auto` 斜杠命令**：无参数，每次调用翻转开关状态（开 ⇄ 关）
2. **状态持久化**：开关状态写入项目根目录 `.intentflow/guard-state.json`，重启后保持
3. **守卫放行逻辑接入开关**：ToolAccessGuard 在开关关闭时跳过所有确认（edit/write/bash）
4. **切换状态提示**：切换时 notify 告知用户当前模式；放行过程静默，不逐次提示

## 核心功能

### 核心功能1：`/guard-auto` 切换命令
- **能力**：系统能够通过斜杠命令 `/guard-auto` 无参数翻转守卫开关状态，并即时生效
- **业务价值**：用户可在会话中随时进入 auto 模式（放行）或恢复审查模式，无需重启或改环境变量

### 核心功能2：开关状态持久化
- **能力**：系统能够将开关状态读写到项目根目录 `.intentflow/guard-state.json`，跨 session 保持
- **业务价值**：用户设置一次后，后续会话保持相同审查策略，无需重复切换

### 核心功能3：守卫放行逻辑接入开关
- **能力**：系统能够在开关关闭时跳过 edit/write/bash 的全部确认拦截（含危险 bash 检查），直接放行
- **业务价值**：实现"关掉审查"的核心意图，放行模式与现有 PI_EXT_SKIP 子 agent 放行机制兼容共存

## 业务规则

### 放行判定（OR 关系）
- **场景**：tool_call 事件到达 ToolAccessGuard
- **行为**：`accessPolicy.shouldSkip('confirm-edit') == true` **或** 开关状态为关闭 → 直接放行，不弹任何确认框
- **异常处理**：两条路径互不影响；开关仅作用于主会话守卫，不改变 PI_EXT_SKIP 语义

### 开关默认值
- **场景**：`.intentflow/guard-state.json` 不存在或内容损坏/非法
- **行为**：视为"开启拦截"（默认安全态），按现有逻辑正常弹确认框
- **异常处理**：读取失败不报错，静默回退默认值；文件损坏时下次切换会覆盖修复

### 切换与持久化
- **场景**：用户执行 `/guard-auto`
- **行为**：翻转内存状态 → 写入 `.intentflow/guard-state.json` → notify 提示当前模式（"守卫已关闭：edit/write/bash 不再确认" / "守卫已开启：恢复确认审查"）
- **异常处理**：写入失败 → notify 报错（error 级别），内存状态保持已翻转值（本次会话生效），不阻塞命令

### 子 agent 环境
- **场景**：子 agent 进程内 tool_call 到达守卫
- **行为**：沿用现有 PI_EXT_SKIP 放行逻辑，开关状态不参与子 agent 判定（子 agent 本就不拦截，无行为差异）
- **异常处理**：无

## 预设测试

> 从用户视角可执行的测试步骤，验证功能是否符合预期。

### 前置条件
- 项目已加载 IntentFlow 扩展（pi 会话中）
- 确认 `.intentflow/guard-state.json` 不存在（或内容为开启状态）

### 测试步骤

1. **[默认拦截]**：让 agent 执行一次 `edit` 或危险 `bash` 命令
   **预期结果**：弹出确认框，取消则 block，与现状一致

2. **[关闭开关]**：执行 `/guard-auto`
   **预期结果**：notify 提示「守卫已关闭」，`.intentflow/guard-state.json` 生成且内容表示关闭

3. **[放行生效]**：让 agent 再次执行 `edit`/`write`/危险 `bash`
   **预期结果**：不弹任何确认框，工具直接执行成功

4. **[重新开启]**：再次执行 `/guard-auto`
   **预期结果**：notify 提示「守卫已开启」，随后 agent 执行 edit 重新弹出确认框

5. **[重启保持]**：关闭开关后退出 pi，重新启动进入同一项目
   **预期结果**：状态保持关闭，agent 执行 edit 直接放行（无需重新切换）

6. **[子 agent 不受影响]**：开关关闭状态下 spawn 子 agent 并让其执行 edit
   **预期结果**：子 agent 行为与之前一致（PI_EXT_SKIP 放行），无异常

### 异常场景

- **[配置文件损坏]**：将 `.intentflow/guard-state.json` 内容改为非法 JSON → 执行 edit → 正常弹确认框（默认安全态）；执行 `/guard-auto` → 正常切换并覆盖修复文件
- **[写入失败]**：将 `.intentflow/` 目录设为只读 → 执行 `/guard-auto` → notify 报错，但本次会话切换仍生效
- **[连续切换]**：连续执行多次 `/guard-auto` → 每次状态正确翻转，无累积错误

## 边界收束

**此时必做**：
- `/guard-auto` 命令注册与切换逻辑（缺少则开关不可用）
- ToolAccessGuard 放行条件接入开关状态（缺少则关闭无效）
- `.intentflow/guard-state.json` 读写与默认安全态回退（缺少则无法持久化）
- extension.ts 注册新命令（缺少则命令不生效）

**此时不做**：
- 分规则开关（独立控制 edit / bash）— 用户已确认全局总开关；待出现"只想放行 edit 保留 bash 保护"的真实诉求时再做
- 切换时安全确认弹窗 — 用户已确认直接切换，状态提示即反馈；若后续误关事故频发再评估
- TUI 状态组件（常驻显示当前模式）— 斜杠命令 + notify 已满足；待用户反馈"记不住当前模式"时再做
- 跨项目共享开关状态（用户主目录级配置）— 已确认按项目隔离；待出现多项目统一管理诉求时再做
- CLI flag（启动时指定状态）— 与运行时切换诉求不符；待出现"启动即放行"场景时再做
