## 会话 2026-06-14 的 UI 哲学灵感

**核心思想**：UI 从"人管理的美学"变成"AI 能计算的计算题"。

不是教 AI "好看"，而是定义好**约束集**让 AI 算：
- 颜色用色板 token + 对比度公式 → AI 算配色
- 间距用 token 集（4px/8px/16px/32px）→ AI 算留白
- 尺寸用百分比 + min/max 约束 → AI 算布局
- 断点 + 宽度比例 → AI 算响应式

有待造的组件契约规范 `intent_fmt/Component.md`，但缺一个 UI 项目来磨。等有了项目再动手，设计纲领已经有了。

1. **`MCPServer.ts` 的 `as any`** — MCP SDK 的 `CallToolRequestSchema` 入参是 `any` 类型，无法完全避免
2. **工具 `catch` 丢失堆栈** — 所有工具用 `throw new Error(msg)` 而非 `{ cause }`，但当前上下文 AI 调用方不消费 `cause` 链，改了也没收益

## 5. 协议审阅待议项（非紧急，存档待需）

> 状态标记：✅ 已实施 / 🔄 优化中 / ❌ 未实施

1. **布局模型扩展** ❌：当前仅支持「百分比绝对定位」。未来可引入 Flexbox 或 Grid 协议字段（如 display: flex 相关属性），放在 css 内。
2. **生产错误边界** ❌：当前策略为「直接抛不兜底」。若需生产友好处理，可用 Vue errorHandler 捕获后展示 overlay + 重试按钮。
3. **behavior / state 集成测试** ❌：当前只测 state 和 behavior 各自内部，未测 invokeAction 与 state 副作用的联动。
4. **编排组件示例** ❌：capability-map 本身就是编排实例，可考虑在 examples/ 下抽出简化版。
5. **文本节点性能** 🔄：已接入 @chenglou/pretext（2.8k stars，React 核心成员开发），`engine/pretext.ts` 已替换为官方库封装。当前简单文本由 Leafer 原生属性处理，复杂排版（connection-line 浮动文本、多行换行）待接入。
6. **协议版本管理** ❌：可在 ComponentNode 中增加 version 字段（如 '1.0.0'），便于解析器兼容。
7. **Pretext 文字排版集成** ❌：TextHeightResolver 仍用 DOM measure 暂代，Pretext 为预留状态。接入后可实现零回流排版计算，替换现有 resolveText() 实现。路线：先完成 Pretext 核心 prepare + layout 两阶段实现，再集成到 converter。
8. **性能监控与调试能力** ❌：当前无帧率、换算耗时、渲染节点数等指标。可在后续新增 profiler.md 或 performance.md 定义关键指标（console.time / PerformanceObserver），但不急。
9. **错误恢复策略** ❌：当前已有第 2 条（UI 层面错误捕获），此条侧重系统层面——错误上报机制（如 Sentry）和用户可见的降级提示（如"渲染失败，请刷新"）。待生产环境需要时补充。
10. **动画变量引用实现路径** ❌：behavior.md 定义的 motion.displacement.x 支持 '{dx}' 变量引用，但变量来源未明确——是 invokeAction 的 payload 传入，还是状态机上下文。当前能力地图未使用 motion，待实际使用动画时细化。
