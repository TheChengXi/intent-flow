# later-on 备忘录：codebase-health-check

> 本 feature 边界外、但值得后续考虑的想法。不做"永远不做"判断，只记录延后条件。

## 1. 健康检查固化为可重复脚本/CLI 命令
- **想法**：本次体检由 AI 协作者一次性执行；后续可把检查维度固化（如 `iflow health-check` 命令或 npm script），支持持续体检
- **延后条件**：出现定期体检诉求、或团队需要非 AI 方式自助体检时

## 2. 过大文件自动拆分
- **想法**：>400 行文件本次只报告不拆；拆分涉及接口重排与行为验证，属结构性重构
- **延后条件**：拆分设计独立 feature（先设计后执行）时

## 3. 依赖漏洞/CVE 审计
- **想法**：本次未查 npm 依赖安全（需联网查询漏洞库，属安全范畴）
- **延后条件**：发布新版本或引入新依赖前

## 4. 运行期行为验证
- **想法**：本次为静态体检，未跑完整测试套件验证运行期行为
- **延后条件**：本次修复涉及行为变更、或需要建立测试基线时（可考虑 vitest 全量跑一遍）

## 5. @intent 与代码行为一致性自动校验
- **想法**：本次只查 @intent 存在性与非空，未校验描述与代码实际行为是否匹配（需语义判断，静态工具难覆盖）
- **延后条件**：intent 语义分析能力成熟、或出现 @intent 与代码明显脱节的案例时

## 6. webview 子项目深度体检
- **想法**：webview（独立 Vue 应用）本次仅做 @intent/文件大小扫描，未做其内部结构体检（依赖、组件边界、Vue 最佳实践）
- **延后条件**：webview 进入活跃迭代期时

## 7. 测试文件 @intent 强制化
- **想法**：本次测试文件 @intent 为"建议补"；若后续测试文件检索/理解成为痛点，可升级为强制规则
- **延后条件**：测试规模增长、检索测试文件成本上升时
