# Component Protocol — 组件协议族

## 这是什么

一份纯粹的组件规范，定义**组件应该长什么样、怎么动、运行时的数据怎么流动**。

不关心谁执行它——AI 生成、手写代码、低代码平台都可以作为它的执行端。

## 这不是什么

- ❌ 不是 AI 工作指令（那是 skill 的事）
- ❌ 不是代码生成器
- ❌ 不是框架绑定（举例用 Vue，但协议本身无关）

## 协议族的构成

```
component-protocol/
  ├── README.md                  ← 本文件
  ├── 01-static-structure.md     ← 静态结构约定
  ├── 02-behavior-contract.md    ← 交互行为约定
  └── 03-runtime-data-schema.md  ← 运行时数据契约
```

### 三份协议的定位

```
01 静态结构 ────── 定义组件树长什么样（递归嵌套）
                      │
                      ▼
02 交互行为 ────── 定义每个组件怎么动（状态机 + 运动接口）
                      │
                      ▼
03 运行时数据 ──── 定义运行中的数据如何被外部读取（AI 接入点）
```

## 核心原则

| 原则 | 说明 |
|------|------|
| **组件第一公民** | 一切皆组件，组件可以容纳组件 |
| **高内聚** | 每个组件自洽：自己的结构、状态、行为自己定义 |
| **低耦合** | 组件之间只通过 props 通信，不操作对方的交互逻辑 |
| **数据附属于组件** | 没有独立的数据层，数据是静态结构和交互行为的交集 |
| **人机分界** | 机器（AI）负责数据结构化和行为可计算化，人类负责审美判断 |
| **内容分离** | 文案（content）和结构（structural）从数据层面分离，AI 只搭结构，文案由外部注入 |

## 默认技术语境

- 组件化框架默认参照 **Vue**（单文件组件、props 向下、events 向上）
- CSS 单位采用 **百分比 + token 体系**（不锁定 px）
- 类型描述采用可读 schema（不锁定 TypeScript）

但协议本身不依赖任何框架——你把这份规范拿到 React、Svelte、Solid 上都能用。

## 术语

| 术语 | 含义 |
|------|------|
| **组件节点** | 组件树中的一个单元，有自己的 identity 和 type |
| **静态结构** | 组件树在编译/设计时的形状描述 |
| **交互行为** | 组件在运行时的状态迁移和动作响应 |
| **运动轨迹** | 动作执行时的位移、时长、缓动等参数 |
| **运行时数据** | 组件在运行中暴露给外部的状态快照 |
