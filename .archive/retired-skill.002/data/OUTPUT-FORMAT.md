# 数据层设计文档输出格式

当所有数据模型设计完成后，按照以下格式输出设计文档：

```markdown
# 数据层设计文档：[项目名称]

## 数据实体

### [实体名称1]
**用途**：[这个实体的作用]

**字段**：
- `id`: `string` - 唯一标识（必填）
- `fieldName`: `type` - [字段说明]（必填/可选）
- ...

**验证规则**：
- `fieldName`: [验证规则描述]
- ...

**关系**：
- 与 [实体2] 的关系：[一对一/一对多/多对多]
- 关系说明：[关系的业务含义]

### [实体名称2]
...

## 数据仓库

### [实体名称1]Repository
**职责**：管理 [实体名称1] 的数据持久化

**接口定义**：
- `create(entity: Entity1): Promise<Entity1>` - 创建实体
- `findById(id: string): Promise<Entity1 | null>` - 根据 ID 查询
- `findAll(): Promise<Entity1[]>` - 查询所有
- `update(id: string, entity: Partial<Entity1>): Promise<Entity1>` - 更新实体
- `delete(id: string): Promise<void>` - 删除实体
- [自定义查询方法]

**存储方式**：[PostgreSQL/MySQL/MongoDB/SQLite/文件系统/内存等]

**实现要点**（供需求转译参考）：

#### findById 方法
- **输入验证**：ID 必须是有效的 UUID 格式
- **查询方式**：使用参数化查询防止 SQL 注入
- **返回规则**：找不到时返回 null，不抛出异常
- **错误处理**：数据库连接失败时抛出 DatabaseError
- **性能考虑**：ID 字段需要建立索引

#### create 方法
- **输入验证**：验证所有必填字段非空
- **ID 生成**：自动生成 UUID 作为主键
- **事务支持**：需要在事务中执行
- **错误处理**：唯一约束冲突时抛出 DuplicateError
- **返回值**：返回包含生成 ID 的完整实体

#### update 方法
- **输入验证**：至少有一个字段需要更新
- **部分更新**：支持 Partial 类型，只更新提供的字段
- **并发控制**：使用乐观锁或版本号防止并发冲突
- **错误处理**：实体不存在时抛出 NotFoundError

#### delete 方法
- **软删除 vs 硬删除**：[说明使用哪种方式]
- **级联删除**：[说明是否需要级联删除关联数据]
- **错误处理**：实体不存在时静默成功（幂等性）

**依赖**：
- Database 连接池
- Logger 日志服务

### [实体名称2]Repository
...

## 数据服务（可选）

### [服务名称1]Service
**职责**：[服务的职责描述，例如：跨实体的聚合查询]

**接口定义**：
- `methodName(params): ReturnType` - [方法说明]
- ...

**实现要点**（供需求转译参考）：

#### methodName 方法
- **输入验证**：[参数验证规则]
- **业务逻辑**：[核心处理步骤]
- **错误处理**：[可能的错误类型]
- **性能考虑**：[缓存、批量处理等]

**依赖**：
- [依赖的仓库]
- [依赖的其他服务]

### [服务名称2]Service
...

## 数据流向

### 创建流程
[描述数据创建的流程]

### 查询流程
[描述数据查询的流程]

### 更新流程
[描述数据更新的流程]

### 删除流程
[描述数据删除的流程]

## 数据验证

### 实体级验证
[描述实体级别的验证规则]

### 业务级验证
[描述业务级别的验证规则]

## 错误处理

### 数据不存在
**场景**：查询或更新不存在的实体
**处理方式**：
- 查询操作：返回 null
- 更新操作：抛出 NotFoundError
- 删除操作：静默成功（幂等性）

### 数据冲突
**场景**：唯一约束冲突、并发更新冲突
**处理方式**：
- 唯一约束冲突：抛出 DuplicateError，包含冲突字段信息
- 并发更新冲突：抛出 ConcurrentModificationError，提示重试

### 验证失败
**场景**：输入数据不符合验证规则
**处理方式**：
- 抛出 ValidationError，包含详细的字段错误信息
- 错误信息格式：`{ field: 'email', message: 'Invalid email format' }`

### 数据库错误
**场景**：连接失败、查询超时、事务失败
**处理方式**：
- 抛出 DatabaseError，包含原始错误信息
- 记录详细日志供排查
- 不暴露敏感的数据库信息给上层

## 性能优化

### 缓存策略
[是否需要缓存？缓存什么数据？]

### 索引设计
[如果使用数据库，需要哪些索引？]

### 批量操作
[是否需要批量操作接口？]
```
