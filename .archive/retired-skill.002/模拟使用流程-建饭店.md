# 建一个饭店——模拟使用流程

## 开场

**用户：** 我想建一个饭店。

**AI：** 好，这个饭店是可视化的对吧？我们一步步来。

先确认第一个问题——**你这个饭店需要几个页面？**

常规饭店一般包括：
- 首页/招牌页
- 菜品展示页
- 支付页
- 客户信息页
- 内部商品布局管理页

你有这些页面之外还要加别的吗？或者哪些不要？

**用户：** 都要，再加一个订单历史页吧。

**AI：** 好，合计六个页面，记下了。

---

## Step 1 — 页面清单（商讨完毕）

```
产出：页面清单

  ├─ 首页/招牌页
  ├─ 菜品展示页
  ├─ 支付页
  ├─ 客户信息页
  ├─ 内部商品布局管理页
  └─ 订单历史页
```

AI 注：页面清单不含任何技术细节，只是和人类达成共识的目录。

---

**AI：** 好，六个页面。接下来我们一个页面一个页面地细化。

先从 **首页/招牌页** 开始——它的静态结构怎么搭？

比如说：
- 顶部要不要导航栏？
- 中间是饭店名字 + 招牌图 + 一句口号？
- 底部要不要页脚？

大概的高低宽比例你心里有数吗？

**用户：** 顶部导航栏占 10% 高度，中间招牌区占 70%，底部页脚 10%，中间招牌区左边是饭店名字右边是图片。

**AI：** 可以。那颜色呢？你有想好的主色吗？没有的话我调个配色方案给你选。

**用户：** 你出方案吧，暖色系。

**AI：** （调 ColorUI API）

```
GET https://colorui.io/api/v1/palette?prompt=暖色系，饭店风格，5色
```

返回了一套方案：

```
primary   #C73E1D  ← 招牌红棕
secondary #F5A623  ← 暖金黄
accent    #8B6914  ← 深古铜
bg        #FFF8F0  ← 米白
text      #2C1810  ← 深褐
```

**用户：** 就这套。

---

## Step 2 — 静态结构（首页/招牌页，商讨完毕）

```
产出：01 静态结构

root:
  identity: "home"
  type: "page"
  props:
    - name: "bgColor"
      type: "token"
      kind: "structural"
      value: "bg"
  css:
    width: "100%"
    height: "100vh"
    tokens: ["bg", "text"]
  children:
    - identity: "home.navbar"
      type: "navigation-bar"
      props:
        - name: "menuItems"
          type: "MenuItem[]"
          kind: "content"          ← 文案，占位
          required: true
      css:
        width: "100%"
        height: "10%"
        tokens: ["primary", "text"]

    - identity: "home.hero"
      type: "hero-section"
      props:
        - name: "title"
          type: "string"
          kind: "content"          ← 文案，占位
          required: true
          description: "饭店名称"
        - name: "slogan"
          type: "string"
          kind: "content"          ← 文案，占位
          description: "口号"
      slots:
        - name: "heroImage"
          cardinality: "0-1"       ← 图片插槽
      css:
        width: "100%"
        height: "70%"
        tokens: ["secondary", "accent"]

    - identity: "home.footer"
      type: "footer-bar"
      props:
        - name: "copyright"
          type: "string"
          kind: "content"
      css:
        width: "100%"
        height: "10%"
        tokens: ["primary", "text"]
```

继续把剩下五个页面的静态结构按同样方式走完。

---

**AI：** 六个页面的静态结构都搭好了。接下来第三步——**每个组件的交互逻辑。**

我们从最简单的开始，**首页的导航栏**：

导航栏的菜单项，你是想点击就跳转页面，还是要带下拉子菜单？

**用户：** 点击跳转就行，不要下拉。

**AI：** 好，那导航栏的交互很简单：

```yaml
identity: "home.navbar"
type: "navigation-bar"

stateMachine:
  states:
    - name: "idle"
    - name: "active"
  transitions:
    - from: "idle"  to: "active"  trigger: "user"  via: "clickItem"
    - from: "active" to: "idle"   trigger: "system" via: "navigated"

actions:
  - name: "clickItem"
    input:
      itemId: { type: "string" }
    output:
      targetPage: { type: "string" }
    effects:
      - type: "state"
        target: "active"
      - type: "emit"
        target: "navigate"
```

**用户：** 对，就这样。

---

**AI：** 那 **菜品展示页** 呢？菜品列表里的卡片要不要交互行为？比如悬停高亮？点击展开详情？

**用户：** 悬停的时候卡片稍微放大 + 阴影加重，点击弹出一个详情弹窗。

**AI：** 可以，记下了：

```yaml
identity: "menu.dish-card-1"
type: "dish-card"

stateMachine:
  states:
    - name: "idle"
    - name: "hover"
    - name: "expanded"
  transitions:
    - from: "idle"   to: "hover"    trigger: "user" via: "pointerEnter"
    - from: "hover"  to: "idle"     trigger: "user" via: "pointerLeave"
    - from: "idle"   to: "expanded" trigger: "user" via: "click"
    - from: "hover"  to: "expanded" trigger: "user" via: "click"
    - from: "expanded" to: "idle"   trigger: "user" via: "closeDetail"

actions:
  - name: "hover"
    motion:
      type: "transition"
      duration: "200ms"
      easing: "ease-out"
      properties: ["transform", "box-shadow"]

  - name: "click"
    output:
      dishId: { type: "string" }
    effects:
      - type: "state"
        target: "expanded"
```

---

……六个页面所有组件的交互逻辑走完。

## 最终产出总览

```
component-protocol/
  │
  01 静态结构 ← 六棵组件树，每棵对应一个页面
  │  每个节点标注了 kind: structural / content
  │  content 字段留作占位，文案等饭店老板自己填
  │
  02 交互行为 ← 每个组件自洽的状态机 + 动作 + 运动参数
  │  共约 24 个组件，40+ 条状态迁移，30+ 个动作
  │
  03 运行时数据 ← 协议内在约束
      每个组件的 dryRun 接口可被 AI 或测试脚本直接调用
      "AI 先模拟一遍，确认数据正确，再通知 UI 渲染"
```

**用户：** 好，差不多了，颜色方案也定了，我现在去准备各个页面的具体文案和图片，你先把骨架代码生出来。

**AI：** 行。文案和图片你填空，我先按照组件树 + 行为契约生成 Vue 代码。颜色 token 已经代入，运动轨迹写成 transition 和 spring 参数。
