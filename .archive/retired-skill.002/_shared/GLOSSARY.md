# CCD 术语表

## 核心注释

### @intent
**用途**：文件级注释，描述这个文件在系统中的业务角色和设计意图

**位置**：文件顶部

**不是什么**：
- ❌ 不是类名/函数名的翻译
- ❌ 不是"这个文件叫什么"
- ❌ 不是简单的功能列表

**是什么**：
- ✅ 这个文件为什么存在
- ✅ 它在系统中的业务价值
- ✅ 它被谁使用，用来做什么
- ✅ 它与其他模块的关系

**示例 - 错误**（只是翻译）：
```
// @intent 用户数据仓库
export interface UserRepository { ... }
```

**示例 - 正确**（表达设计意图）：
```
/**
 * @intent
 * 用户数据持久化的抽象边界。
 * 应用层通过这个接口访问用户数据，无需了解存储细节（数据库/缓存/文件）。
 * 支持多种实现：MySQL、MongoDB、内存等。
 */
export interface UserRepository { ... }
```

**示例 - 用例**：
```
/**
 * @intent
 * 核心编排用例。协调数据层三个能力（扫描、分析、聚类），
 * 生成项目能力清单。这是 MCP 工具的直接调用入口。
 * 输出的能力清单用于：
 * - 设计师快速理解项目能力边界
 * - 大模型识别项目的功能模块
 * - 需求分析时追踪能力缺口
 */
export interface IGenerateCapabilityListUseCase { ... }
```

### @entity
**用途**：标记数据实体

**位置**：实体定义上方

**说明**：用于标识核心业务实体，通常与 @intent 一起使用

### @contract
**用途**：方法契约，描述方法的输入、输出、副作用

**位置**：方法签名上方

**包含内容**：
- 输入参数的约束
- 返回值的格式
- 可能抛出的错误
- 副作用（如：修改数据库、调用外部API）

**生成时机**：需求转译阶段

### @step
**用途**：实现步骤，描述方法的执行流程

**位置**：方法体内部

**包含内容**：
- 按顺序列出的执行步骤
- 每个步骤的目的和操作

**生成时机**：需求转译阶段

### @boundary
**用途**：边界定义，描述输入验证、输出格式、错误处理

**位置**：方法签名上方或方法体内部

**包含内容**：
- 输入验证规则
- 输出格式规范
- 错误类型和处理方式

**生成时机**：需求转译阶段

## 架构层次

### 数据层（Data Layer）
**职责**：管理数据的持久化和访问

**包含**：
- 实体定义（Entity）
- 数据仓库接口（Repository）
- 数据服务接口（Service，可选）

**依赖**：不依赖其他层（最底层）

### 应用层（Application Layer）
**职责**：实现业务逻辑和用例编排

**包含**：
- 用例/命令处理器（Use Case / Command）
- 应用服务（Application Service）
- 上下文管理器（Context Manager）

**依赖**：依赖数据层

### 适配层（Adapter Layer）
**职责**：连接外部世界和应用核心

**包含**：
- 输入适配器（Input Adapter）：UI、API、CLI、Chat
- 输出适配器（Output Adapter）：数据库实现、外部API、文件系统
- DTO/映射器（DTO / Mapper）

**依赖**：依赖应用层

## 工作流程

### 设计阶段
**目标**：生成接口定义和设计文档

**输出**：
- 接口/类定义（只有签名，无实现）
- @intent 注释
- 详细设计文档

**不生成**：@contract、@step、@boundary 注释

### 需求转译阶段
**目标**：将设计文档转译为 CDD 注释

**输入**：接口定义 + 设计文档

**输出**：
- 实现类骨架
- @contract、@step、@boundary 注释
- 构造函数和依赖注入

**不生成**：具体实现代码

### 代码编译阶段
**目标**：根据 CDD 注释生成完整实现

**输入**：带有 CDD 注释的文件

**输出**：
- 完整实现代码
- 辅助方法
- 错误处理逻辑
