# 应用层设计文档输出格式

当所有应用层设计完成后，按照以下格式输出设计文档：

```markdown
# 应用层设计文档：[项目名称]

## 用例（Use Cases）

### 用例1：[用例名称]
**职责**：[用例的职责描述]

**业务规则**：
- [规则1]
- [规则2]
- ...

**前置条件**：
- [条件1]
- [条件2]
- ...

**后置条件**：
- [条件1]
- [条件2]
- ...

**依赖**：
- 数据层：[依赖的数据层模块]
- 应用层：[依赖的其他应用层模块]

**Intent**：[一句话描述用例功能]

### 用例2：[用例名称]
...

## 应用服务

### [服务名称1]Service
**职责**：[服务的职责描述]

**方法**：
- `methodName(params): ReturnType` - [方法说明]
- ...

**依赖**：
- [依赖的数据层仓库/服务]

**错误处理**：
- [错误类型1]：[如何处理]
- [错误类型2]：[如何处理]

**Intent**：[一句话描述服务功能]

### [服务名称2]Service
...

## 命令处理器

### [命令名称1]Command
**职责**：[命令的职责描述]

**输入参数**：
- `paramName`: `type` - [参数说明]
- ...

**输出结果**：
- `returnType` - [返回值说明]

**依赖**：
- [依赖的应用服务/数据层服务]

**错误处理**：
- [错误类型1]：[如何处理]
- [错误类型2]：[如何处理]

**Intent**：[一句话描述命令功能]

### [命令名称2]Command
...

## 上下文管理器

### [上下文名称1]ContextManager
**职责**：[上下文管理器的职责描述]

**管理的状态**：
- `stateName`: `type` - [状态说明]
- ...

**生命周期**：
- **创建时机**：[何时创建]
- **销毁时机**：[何时销毁]

**作用域**：[全局/会话级/请求级]

**Intent**：[一句话描述上下文管理器功能]

### [上下文名称2]ContextManager
...

## 业务流程

### 用例流程
用户请求 → 适配层 → 应用层命令 → 应用服务 → 数据层 → 返回结果 → 适配层响应

### 数据流向
[描述数据在应用层中的流向]

### 错误处理流程
[描述错误处理的流程]

## 依赖关系图

```
[用例1]
  ├─ [命令1]Command
  │   ├─ [应用服务1]Service
  │   │   ├─ [数据层仓库1]
  │   │   └─ [数据层服务1]
  │   └─ [上下文1]ContextManager
  └─ [命令2]Command
      └─ [应用服务2]Service
          └─ [数据层仓库2]

[用例2]
  ├─ [命令3]Command
  │   └─ [数据层仓库3]
  └─ [上下文2]ContextManager
      └─ [数据层服务2]
```

## 性能优化

### 缓存策略
[是否需要缓存？缓存策略是什么？]

### 懒加载
[是否需要懒加载？哪些模块需要懒加载？]

### 批量处理
[哪些操作需要批量处理？]

## 测试策略

### 单元测试
[如何测试应用服务和命令处理器？]

### 集成测试
[如何测试应用层和数据层的集成？]

### Mock 策略
[如何 Mock 数据层依赖？]
```
