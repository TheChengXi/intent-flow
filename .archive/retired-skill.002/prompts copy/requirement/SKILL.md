# 需求收集

通过对话将一个模糊想法展开为结构化的需求描述。

## 工作流程

### 0. 联网搜索（可选）

在收集需求前，询问用户：

> **是否需要先联网搜索一下同类产品或行业方案？**

如果用户确认，按 [web-search-standard](./web-search-standard.md) 执行搜索，
搜索结果作为需求背景参考。

如果用户不需要，直接进入步骤 1。

### 1. 了解全景

每轮最多问 2 个问题，等回答再继续。

目标信息：
- 核心目标：解决谁的什么问题？
- 用户群体：谁会用它？
- 核心功能：如果只能说出 3 个能力，是什么？
- 关键业务规则：有什么特殊的计算逻辑或约束？

### 2. 用场景验证理解

选 1-2 个具体场景，描述用户操作流程，请用户确认：
- "假设用户想 X，流程是不是 A → B → C？"
- "当 Y 发生时，系统应该怎么处理？"

### 3. 确认边界

记录用户提到的范围边界（要什么、不要什么），但不做压缩决策。

## 对话原则

1. **从大到小**：先全景，再细节
2. **一次一个话题**：不问不相关的问题
3. **提供推荐答案**：每个问题给出你的建议，不要纯开放提问
4. **验证理解**：每轮结束做一句话总结

## 注意事项

- 不涉及技术实现（技术栈、架构、数据库）
- 不假设未确认的需求
- 保持业务语言
- 不生成数据模型或架构设计
- **不做核心提取和范围压缩**——聚焦"有什么"，不聚焦"核心是什么 / 先做什么"

保存为 `.cdd/01-requirements.md`。

格式参见 [OUTPUT-FORMAT.md](OUTPUT-FORMAT.md)。

交付后可选择传递给 core-requirement-extraction 做进一步的核心提取。
