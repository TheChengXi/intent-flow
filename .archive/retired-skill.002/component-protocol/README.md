# Component Protocol — 组件协议族

一套**声明式 UI 协议**，定义组件长什么样、怎么动、运行时数据怎么流。

协议本身与框架无关——Vue、React、Leafer Canvas、甚至低代码平台都可以作为执行端。协议只关心契约，不关心谁执行它。

## 一句话定位

> UI 是可声明、可递归的组件树。交互是可计算、可验证的状态机。运行时数据是可读、可模拟、可追溯的。

## 核心原则

| 原则 | 说明 |
|------|------|
| **组件第一公民** | 一切皆组件，组件可以容纳组件 |
| **高内聚** | 每个组件自洽：结构、状态、行为自己定义 |
| **低耦合** | 组件间只通过 props 通信，不操作对方交互逻辑 |
| **数据附属于组件** | 没有独立数据层，数据是静态结构和交互行为的交集 |
| **人机分界** | AI 负责结构化与可计算化，人类负责审美判断 |
| **内容结构分离** | 文案由外部注入，AI 只搭结构不写文案 |
| **目录即组件，路径即意图** | 每个组件目录四文件（protocol/render/behavior/state），对应协议/渲染/行为/数据四层。
  这种拆分不是为了人类书写方便，而是为了：
  - 让 AI 在生成/修改时能精准定位到单一职责文件
  - 让 Converter / Generator 能够按文件粒度进行增量编译和热替换
  - 让组件在技术栈迁移时只替换单一文件，不影响其他两层
  - 其中 state.ts 仅在组件需要自行通信时使用 |

## 映射关系

```
协议维度            Leafer UI 映射          为什么完美匹配
───────────────────────────────────────────────────────────
01 静态结构         场景图 Scene Graph       Leafer 本身就是 Group/Leaf 树
（递归组件树）                                   identity → LeaferNode.id
                                               slots → Group.add()

02 交互行为         Event 系统              onPointerDown/onDrag 直接绑定
（状态机/动作）      + 自定义属性                运动轨迹用 @leafer-ui/animate

03 运行时数据       纯数学属性               bounds/x/y 都是纯数据
（dryRun/快照）                                   dryRun = 改内存数据不渲染
                                               invokeAction = 验证后 update()
```
