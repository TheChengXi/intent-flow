# Phase 3：集成验证 & 重构

## 输入

Phase 2 产出的所有已测试文件。

## 流程

### 1. 写集成测试

集成测试不 mock，用真实实现串联多个模块。每个核心通路写 1–2 个测试。

典型集成场景：用户请求 → 适配层 → 用例层 → 数据层 → 返回结果。

### 2. 跑全量测试

```
单元测试（Phase 2）+ 集成测试（Phase 3）→ 全绿
```

### 3. 重构

逐一检查以下候选：

- 重复代码 → 提取共享
- 函数过长 → 拆私有方法（测试不动，仍在公开接口上）
- 职责模糊 → 拆/合类
- 基本类型偏执 → 引入值对象

**每步重构后跑测试**，绿了再走下一步。

### 4. 端到端验证（如有）

如果项目有端到端验证手段（CLI、MCP 工具、API），跑一遍确认整个流程走通。发现问题回 Phase 1/2 修，不要在 Phase 3 直接改代码跳过测试。

## 完成条件

- 集成测试全绿
- 全量测试套件全绿
- 重构完成，每步中间状态测试均绿
