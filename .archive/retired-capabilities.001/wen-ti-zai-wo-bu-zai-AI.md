# 不要再瞎压缩上下文了

## 起因

当时看着 context 窗口越涨越高，心里一慌，想着：

> "不行，得压缩一下，不然 token 要爆了。"
> "哎呀, 卧槽，/compact这么好使。"

然后我做了一件蠢事：**把需求分析的需求过度压缩，导致 Codex 类的 AI 在理解不充分的情况下，生成了一大堆结构严谨但毫无卵用的代码。**

代价：
- 写了一大堆没必要的抽象接口
- 生成了两个从来没人用过的 MCP 工具（`list_layer_capabilities`、`search_capability_by_keyword`）
- 多花了不知道多少 token 来生成、重构、然后删掉它们
- 还多花了写这个文档的 token（说的就是你，现在在读这段的我）

## 根源

**上下文压缩不是目标，理解才是。**

你以为压缩 = 省钱，实际上压缩 = 让 AI 在信息不足的情况下瞎猜 → 生成垃圾 → 你花更多 token 擦屁股 → 更贵。

## 血泪教训

1. **按当前上下文给你推荐了错误解决方案，不要再为了省上下文乱跳**。上下文就是钱，但错误的代码比上下文更贵。
2. **如果你都不确定自己在说什么，AI 也猜不到**。你压缩掉的细节，AI 会用"看起来最合理但实际上错的"补上。
3. **"求简"的前提是理解了全部，而不是跳过了全部。** 先铺开再收敛，不要试图一步到位。
4. 最后一点：**省了 2000 tokens 的上下文，赔了 50000 tokens 的重构**，这笔账再算不过来就别搞 AI 编程了。

## 关联的尸体

- `ListLayerCapabilitiesTool.ts` — 被过度设计的工具 #1
- `SearchCapabilityByKeywordTool.ts` — 被过度设计的工具 #2
- `ScanIntentsUseCase.ts` — 为了支撑上面两个而诞生的无用用例
- 以及一票 DTO、接口、实体——全是给上面陪葬的
