# 角色是两个概念，不是两个类型

组件的目录里**有什么文件，就有什么能力**。没有预设的分类桶。

一个目录可以有任意组合的 protocol / behavior / state / render。

- 有 `protocol.ts` → 组件有自定尺寸，受协议约束，可被外部协议引用
- 有 `behavior.ts` → 组件有独立交互行为（XState 状态机）
- 有 `state.ts` → 组件自行与外部通信
- 有 `render.ts` → 组件参与渲染场景图

**没有两个固定的桶。每个组件只含它需要的文件。**

同一个组件也可以在演变中增加或移除文件。目录不负责分类，文件清单负责声明能力。

## 协议 是一个概念

当一个组件以 `protocol.ts` 定义自己的尺寸和接口并在多个场景中被引用时，它在扮演**协议**角色。

## 组件间通信

兄弟组件之间不直接通信（约束 #4：不 import 兄弟）。共享状态时，采用**状态提升到最近的编排组件**的方式：

```
编排组件（持有 state.ts）
├── 子组件 A  ← 通过 props 接收数据
└── 子组件 B  ← 通过 props 接收数据
```

子组件不持有共享状态，只消费 props。编排组件的 state.ts 统一管理数据，子组件通过 `invokeAction` 触发状态变更。

如果跨层级较远，通过编排组件逐级传递，或在编排组件的 state.ts 中托管一个全局可读的数据副本。不跨级读写、不走事件总线。
