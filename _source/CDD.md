# Comment-Driven Development (CDD) v2.4.1

## 范式声明

CDD 由“注释即源码”这一核心原则驱动，是一套以人写注释、AI写代码、审查员对标审计为闭环的结构化协作协议。

**注释与代码是两个平等的事实候选。** 注释是首选候选，代码是次选候选。分歧时经由裁决确定最终事实，落选方必须对齐。常规流程中，注释驱动代码。代码经实战检验后，可通过裁决反向覆盖注释。

**适用场景：** 需要长期迭代、多人协作、业务规则复杂的非一次性项目。
**不适用场景：** 快速原型、一次性脚本、个人随手工具。


## 零、核心原则：注释即源码

```
// @contract: functionName (param: Type) => ReturnType | throws ErrorType
// @step: [意图] 第一步
// @step: [意图] 第二步
// @boundary: 当...时，应...
// ↓↓↓ 编译器生成，审查员核对 ↓↓↓
[AI代码]
// @end
```

- 人写注释，AI写代码。注释定义“做什么”，代码是“怎么做”的翻译。
- **常规迭代路径：** 修改注释 → 编译器更新代码 → 审查员审计。
- **反向同步路径：** 代码被直接修改后，代码转译员将代码反向同步为注释。
- **回溯路径：** 编译或审查中发现注释无法执行时，向上游发出回溯请求，闭环修正。


## 一、核心铁律

```markdown
【元规则：AI行为准则】
1. 实事求是。注释是实事，代码是求。审查员检验求是否忠于实事。
2. 具体问题具体分析。只处理当前工作行及其直接依赖，不做全局推测。
3. 不懂就问。注释不清晰、契约冲突、物理不可行时，禁止猜测，必须暂停请求裁决。

【注释即源码】
注释是首选事实来源。AI根据注释生成代码，审查员以注释为标尺审计。

【平等事实原则】
注释与代码分歧时，审查员触发两条路径：
- 路径A（注释为准）：激活转译员确认注释 → 编译器重新编译
- 路径B（代码为准）：激活代码转译员·守护模式，代码反向同步为注释
裁决后二者归一。延后裁决须在 WorkSchedule 记录债务。

【回溯机制】
编译器、审查员、测试策略师发现上游产物无法执行时，有权触发回溯：
1. 输出《回溯请求》：指明问题、描述、建议方向
2. 发送至转译员（注释问题）或产品经理（规则问题）
3. 上游修正后触发重编译
4. 上游拒绝则升级至人类裁决
回溯是内部闭环修正，优先于人类裁决，但不取代人类裁决。

【注释精度准则】
关键路径每个 @step 必须精确到“人类审查员能明确判断对错”的程度。
禁止模糊词（如“校验”、“处理”、“有效”、“合理”）。
正确示例：“校验 username 满足 ^[a-z0-9_]{3,20}$ 且未被占用。不满足则返回 ValidationError。”
非关键路径允许使用 // @simple 标记降低精度要求。

【上下文最小化】
AI每次只读取：
1. 当前工作行的全部注释
2. 被引用函数的 @contract（不含内部实现）
3. 全局 PROJECT_SOUL.md

【契约依赖可追溯】
编译器编译后在 WorkSchedule 记录所依赖的 @contract 版本。
代码转译员（守夜人模式）定期扫描，标记“依赖已过期”的模块。

【核心层演进规则】
修改 PROJECT_SOUL.md 或 BUSINESS_RULES.md 须启动范式版本升级：
1. 迭代规划师召集 Council（产品经理+架构探讨者+转译员）
2. 产品经理提交《PROJECT_SOUL 偏离评估》，无权否决
3. 确认为“演进”后产出草案，由人最终确认
4. CHANGELOG 追加 [PARADIGM SHIFT]，编译器用最新模型重新编译整个项目

【自举与进化边界】
角色提示词可在自举中自我优化，但须遵守：
1. PROJECT_SOUL.md、BUSINESS_RULES.md、本核心铁律不可自动修改
   （“绝对”仅对当前版本有效。版本号+CHANGELOG+Git 是其合法性来源）
2. 适配层（角色提示词、编译规范、审查维度）可优化，须经审查员逻辑一致性审查
3. 所有提示词维护“核心指令预算”（核心指令不超过800字）
4. 提示词增长时，迭代规划师同时生成精简版和完整版，默认使用精简版

【强制工作日志】
完成任务后在 WorkSchedule.md 追加：日期 | 时间 | 执行角色 | 工作简述 | 耗时 | 依赖契约版本
日志超过500行自动归档为 WorkSchedule_v[N].md。

【CHANGELOG 溯源】
每次修改注释或核心文档，追加：
日期 | 文件 | 变更内容 | 变更原因 | 类型([HOTFIX]/[PARADIGM SHIFT]/[ITERATION]/[BACKTRACK])

【决策权原则】
你是飞行员，AI是副驾驶。所有决策权永远在你，AI提供选项，未经确认不得执行。
```

## 四、编译-审查轮巡流程

```
[编译器] 根据注释生成代码，添加 // @end
    ↓ （发现注释无法编译 → 回溯 → 转译员修正 → 重编译）
[代码审查员] 以注释为标尺审计
    ↓ （发现注释不可行 → 回溯 → 转译员修正 → 重编译）
    ├── 注释≠代码 → 裁决路径A/B
    ├── ❌ → 重新编译
    └── ✅ → [测试策略师]
                ↓ （发现注释不可测试 → 回溯 → 转译员修正 → 重编译）
                └── ✅ → 下一模块
```
