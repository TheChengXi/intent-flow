# 阶段 5：View/Chat 层设计

基于前置阶段的文档，通过对话设计 View/Chat 层的用户界面、交互逻辑、事件处理，并生成文件骨架。

## 前置依赖

**必须读取**：
- `.cdd/01-requirements.md`（需求文档）
- `.cdd/02-architecture.md`（架构设计文档）
- `.cdd/03-model-design.md`（Model 层设计文档）
- `.cdd/04-viewmodel-design.md`（ViewModel 层设计文档）

如果这些文件不存在，提示用户先完成前置阶段。

## 核心概念

参见 [GLOSSARY.md](../GLOSSARY.md) 中的术语定义：
- **@intent**：描述文件功能（必须标注）
- **@dependency**：通过 import 语句自动提取（不需要手动标注）

## 工作流程

### 1. 识别界面类型

根据架构设计文档，确定项目的界面类型：

**常见界面类型**：
- **Web 应用**：React/Vue 组件、页面
- **CLI 工具**：命令行交互、参数解析
- **VSCode 扩展**：Webview、TreeView、StatusBar、Command
- **桌面应用**：Electron 窗口、对话框
- **Chat 界面**：对话式交互、消息处理

**询问用户确认**：
- "根据架构设计，这是一个 [界面类型] 项目，是否正确？"
- "需要哪些界面组件？"

### 2. 设计界面结构

根据需求文档和界面类型，设计界面结构：

**Web 应用**：需要哪些页面？哪些组件？页面如何导航？

**CLI 工具**：需要哪些命令？每个命令的参数？如何显示输出？

**VSCode 扩展**：需要哪些命令？哪些视图？哪些状态栏项？

**Chat 界面**：需要哪些对话流程？如何处理用户输入？如何展示响应？

### 3. 设计交互逻辑

针对每个界面组件，设计交互逻辑：

**询问或推荐**：
- 用户可以执行哪些操作？（点击、输入、选择等）
- 每个操作触发什么事件？
- 事件如何传递到 ViewModel？
- ViewModel 的响应如何更新界面？

**交互设计原则**：
- **用户友好**：操作简单直观
- **即时反馈**：操作后立即给出反馈
- **错误提示**：清晰的错误提示和恢复建议
- **加载状态**：长时间操作显示加载状态

### 4. 设计数据绑定

确定界面如何绑定 ViewModel 的状态：

**数据绑定方式**：
- **单向绑定**：ViewModel → View（只读显示）
- **双向绑定**：ViewModel ↔ View（表单输入）
- **事件绑定**：View 事件 → ViewModel 命令

### 5. 设计组件层次

将界面组织成组件层次结构：

**组件分类**：
- **页面组件**：顶层容器，对应一个完整的页面或视图
- **容器组件**：负责数据获取和状态管理
- **展示组件**：纯展示，不包含业务逻辑
- **通用组件**：可复用的基础组件

### 6. 生成文件骨架

根据设计生成文件骨架（@intent + import + 组件结构）：

**生成内容**：
1. **页面组件**（`src/view/pages/` 或 `src/chat/handlers/`）
2. **可复用组件**（`src/view/components/`）
3. **视图工具函数**（`src/view/utils/`）

**文件骨架包含**：
- `@intent` 注释：描述文件的功能
- `import` 语句：声明依赖的 ViewModel 层模块
- 组件结构：只有结构，不实现具体逻辑

## 对话原则

1. **基于需求设计**：所有界面都应该来自需求文档
2. **避免过度设计**：不要设计用不到的界面和组件
3. **考虑用户体验**：界面应该简洁、直观、易用
4. **保持一致性**：界面风格和交互模式应该一致
5. **验证理解**：定期总结已设计的界面和交互，确保理解一致

## 输出格式

当所有 View/Chat 层设计完成后，输出设计文档和文件骨架。

设计文档结构参见 [OUTPUT-FORMAT.md](OUTPUT-FORMAT.md)。

## 特殊情况处理

### 当界面过于复杂时
建议拆分成多个小组件，每个组件负责一个功能。

### 当交互流程复杂时
绘制交互流程图，帮助用户理解交互逻辑。

### 当需要实时更新时
考虑使用 WebSocket、轮询或事件监听机制。

### 当需要离线支持时
考虑使用 Service Worker、LocalStorage 或 IndexedDB。

## 注意事项

- **必须标注 @intent**：每个文件都必须在顶部标注 @intent
- **依赖通过 import 声明**：不需要手动标注 @dependency，系统会自动从 import 语句中提取
- **View 层不直接依赖 Model 层**：必须通过 ViewModel 访问数据
- **保持组件简单**：复杂的逻辑应该在 ViewModel 中处理
- **关注用户体验**：界面应该简洁、直观、响应迅速
- **错误处理要友好**：给出清晰的错误提示和恢复建议

## 最终交付物

当所有 View/Chat 层设计完成后：

1. 将设计文档保存为 `.cdd/05-view-chat-design.md`
2. 生成 View/Chat 层文件骨架到相应目录：
   - `src/view/pages/` - 页面组件骨架
   - `src/view/components/` - 可复用组件骨架
   - `src/chat/handlers/` - Chat 处理器骨架
3. **每个文件都必须标注 @intent**
4. **依赖关系通过 import 语句声明**

至此，整个项目的五个阶段设计全部完成：
- 需求分析 → 架构设计 → Model 设计 → ViewModel 设计 → View/Chat 设计

项目可以进入实现和测试阶段。
