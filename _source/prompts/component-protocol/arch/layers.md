# 五层架构

整个系统分五层，自底向上。这套分层描述的是**抽象职责**，每层的具体技术实现可自由替换。

```
┌──────────────────────────────────────────────────────────┐
│                    ① 协议定义层                           │
│  组件树 + 行为契约 + 数据契约                            │
│  [当前示例: YAML → TS，可用 JSON / TOML / 结构体 替代]   │
├──────────────────────────────────────────────────────────┤
│                    ② 换算层                               │
│  纯函数，协议 % CSS → 运行时 px 坐标                      │
│  框架无关 / 协议无关 / 输入相同输出一定相同               │
│  [任何语言都能实现的纯数学换算，50-80 行]                 │
├──────────────────────────────────────────────────────────┤
│                    ③ 运行时管理层                           │
│  生命周期控制 + 状态调度 + 数据容器 + 页面编排             │
│  [当前示例: Vue 3 + XState + pages/ + overlay/]            │
│  [可替换为: React / Svelte / 游戏主循环 / 无框架纯 TS]    │
├──────────────────────────────────────────────────────────┤
│                    ④ 数据计算层                             │
│  纯数据文字排版计算（零 DOM 回流）                         │
│  [当前示例: Pretext 文本测量]                              │
├──────────────────────────────────────────────────────────┤
│                    ⑤ 渲染执行层                             │
│  场景图构建，每个协议节点映射为场景图节点                  │
│  [当前示例: Leafer Canvas]                                 │
│  [可替换为: Three.js / SDL / OpenGL / 原生 DOM]           │
└──────────────────────────────────────────────────────────┘
```

## 层间依赖

```
协议定义层
     ↓ 编译
换算层（% → px）
     ↓ 换算
运行时管理层
     ↓ 调度
数据计算层
     ↓ 排版
渲染执行层
```

每一层只依赖下层输出，不跨越调用。换算层不读运行时状态，渲染层不调运行时状态管理。

## 层可替换性

| 层 | 抽象职责 | 当前示例实现 | 可替换为 |
|----|---------|-------------|---------|
| 渲染执行 | 场景图构建与绘制 | Leafer（2D Canvas） | Three.js（3D）/ SDL / OpenGL / 原生 DOM |
| 运行时管理 | 生命周期 + 状态调度 + 页面编排 | Vue 3 + XState + pages/ + overlay/ | React / Svelte / 游戏主循环 / 纯 TS |
| 换算 | % → px 纯函数 | 自研 Converter（50-80 行） | 任何语言实现的纯函数 |
| 数据计算 | 零回流文字排版 | Pretext 文本测量 | 自研排版 / DOM measure |
| 协议定义 | 组件树 + 行为 + 数据契约 | YAML → TS | JSON / TOML / C 结构体 / Rust enum |

## 根节点容器尺寸

协议只定义"需要容器尺寸才能换算"，不规定容器来源。
- 当前示例：由 App.vue 中的 100% div 提供，ResizeObserver 监听
- 游戏场景：由窗口系统或摄像机视口提供
- 命令行：由显式传入的 width / height 提供
