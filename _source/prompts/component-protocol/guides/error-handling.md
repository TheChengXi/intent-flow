# 错误处理策略

## 原则：不吞异常，不写冗余兜底

- 协议校验失败 → Zod refine 拦截，抛出结构化错误消息
- 运行时异常（Leafer 实例未就绪、节点不存在）→ 直接抛，不 try-catch 静默
- 无效动作（invokeAction 收到未定义事件）→ 不处理，不写空 else 分支
- Converter 输入异常（非法百分比字符串）→ 抛出 ParseError，不返回默认值

## 分层

| 层 | 错误类型 | 处理方式 |
|----|---------|---------|
| 协议定义 | YAML 结构不合法 | Zod refine 拦截，返回错误报告 |
| 换算 | 非法 % 格式 / 负值 | 抛出 ParseError，不兜底 |
| 运行时 | 无效 invokeAction | 不执行，静默忽略（等同于不存在的事件） |
| 渲染 | Leafer 实例未就绪 | 断言或抛，不 fallback |
| 行为 | 非法状态迁移 | XState 内置处理，不会走到未定义状态 |

## 不做的

- 不写 `if (error) fallbackRender()` 这种"优雅降级"——崩了就是崩了，错误的渲染比崩溃更难调试
- 不存在逻辑路径的分支不写 else
