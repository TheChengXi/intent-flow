# AI 行为边界

## 核心分工

```
人类决定：
  5 主色          ← 色板你定
  图片挑选        ← 你选图，AI 只取宽高
  审美把控        ← 最终好不好看你说了算

AI 计算：
  百分比布局      ← 纯计算，不涉及审美
  运动轨迹参数    ← 原子组件级的动效描述
  颜色代入 token  ← 把人类选的颜色分配到组件
  图片插槽        ← 根据宽高比算占位空间
```

## 流程

### Step 0（可选）：AI 生成色板方案供人类挑选

如果人类还没确定颜色，调 ColorUI API 生成候选方案。返回 5 个 hex 值 + 方案描述。展示给人类，等人挑一套。

> AI 只出示方案，不替人类做决定。人类可以从方案里挑一套，也可以完全自己定。

### Step 1：人类确认 5 主色

人类确认最终 5 个主色（hex 或 tailwind token）— 必填。

其他可选信息：
- **布局意图**（一句话描述）
- **图片插槽**（哪些位置是图片，宽高比）
- **参考链接**（可选：像 XX 产品的风格）

> 如果人类没给全，AI 不替人类做审美决策。只问："这 5 个主色是哪些？"

### Step 2：AI 计算约束

拿到人类输入后，AI 计算：

```
布局参数：
  - 每个模块的百分比宽高（相对于父容器）
  - 间距：百分比而非 px
  - 响应式缩放算法

颜色代入：
  - 5 主色分配到 token 体系（primary / secondary / accent / bg / text）
  - 代入组件

运动轨迹：
  - 每个原子组件标注运动方式（进入/悬停/点击）
  - 描述：持续时长、缓动曲线、位移百分比

图片插槽：
  - 标记 <img slot="hero" ratio="16/9" />
  - 人类后续填入实际图片
```

### Step 3：生成代码

AI 按照计算好的约束生成代码：
- 纯百分比单位（`width: 60%`, `margin-left: 2.5%` 等）
- 颜色仅从 5 主色派生
- 图片位置留插槽，不填充实际图片
- 运动轨迹写成 CSS transition / animation 或 motion 库

### Step 4：人类审美验收

- 人类看效果 → "这个间距大了，缩到 1.5%"
- AI 改参数 → 重新计算 → 重新生成
- 直到人类满意

## 核心原则

| 原则 | 说明 |
|------|------|
| **AI 只算不选** | 不替人类决定颜色、图片、风格方向 |
| **百分比优先** | 所有距离用 %，不写固定 px |
| **原子组件轨迹** | 每个可交互组件都有自己的运动描述 |
| **图片=插槽** | 不生成假图，只标记宽高比 |
| **5 色锁死** | 全局不超过 5 个主色，从 token 派生 |

## 与组件协议的关系

AI 行为边界决定"AI 该算什么、不该算什么"，组件协议决定"组件长什么样、怎么动、数据怎么流"。两者分工明确。
