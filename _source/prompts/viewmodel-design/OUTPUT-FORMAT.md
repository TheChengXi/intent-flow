# ViewModel 层设计文档输出格式

当所有 ViewModel 层设计完成后，按照以下格式输出设计文档：

```markdown
# ViewModel 层设计文档：[项目名称]

## 功能模块

### 模块1：[模块名称]
**职责**：[模块的职责描述]

**状态管理**：
- `stateName`: `type` - [状态说明]
- ...

**命令处理**：
- `CommandName` - [命令说明]
- ...

**依赖**：
- Model 层：[依赖的 Model 层模块]
- ViewModel 层：[依赖的其他 ViewModel 模块]

**Intent**：[一句话描述模块功能]

### 模块2：[模块名称]
...

## 命令处理器

### [命令名称1]Command
**职责**：[命令的职责描述]

**输入参数**：
- `paramName`: `type` - [参数说明]
- ...

**输出结果**：
- `returnType` - [返回值说明]

**依赖**：
- [依赖的 Model 层服务/仓库]

**错误处理**：
- [错误类型1]：[如何处理]
- [错误类型2]：[如何处理]

**Intent**：[一句话描述命令功能]

### [命令名称2]Command
...

## 上下文管理器

### [上下文名称1]ContextManager
**职责**：[上下文管理器的职责描述]

**管理的状态**：
- `stateName`: `type` - [状态说明]
- ...

**生命周期**：
- **创建时机**：[何时创建]
- **销毁时机**：[何时销毁]

**作用域**：[全局/模块级/组件级]

**Intent**：[一句话描述上下文管理器功能]

### [上下文名称2]ContextManager
...

## 角色/功能模块

### [角色名称1]VM
**职责**：[角色的职责描述]

**包含的命令**：
- [命令1]
- [命令2]
- ...

**管理的状态**：
- [状态1]
- [状态2]
- ...

**依赖的上下文**：
- [上下文1]
- [上下文2]
- ...

**Intent**：[一句话描述角色功能]

### [角色名称2]VM
...

## 数据流向

### 用户操作流程
用户操作 → View 事件 → ViewModel 命令 → Model 服务 → 数据更新 → 状态更新 → View 刷新

### 状态更新流程
[描述状态更新的流程]

### 错误处理流程
[描述错误处理的流程]

## 依赖关系图

```
[角色1]VM
  ├─ [命令1]Command
  │   ├─ [Model服务1]
  │   └─ [Model仓库1]
  ├─ [命令2]Command
  │   └─ [Model服务2]
  └─ [上下文1]ContextManager

[角色2]VM
  ├─ [命令3]Command
  │   └─ [Model仓库2]
  └─ [上下文2]ContextManager
      └─ [Model服务3]
```

## 性能优化

### 状态缓存
[是否需要缓存状态？缓存策略是什么？]

### 懒加载
[是否需要懒加载？哪些模块需要懒加载？]

### 防抖/节流
[哪些操作需要防抖或节流？]

## 测试策略

### 单元测试
[如何测试命令处理器？]

### 集成测试
[如何测试 ViewModel 和 Model 的集成？]

### Mock 策略
[如何 Mock Model 层依赖？]
```
