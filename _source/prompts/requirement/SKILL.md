# 需求分析入口 — 路由

本技能不做具体需求分析，只做一件事：**判定入口熵值，路由到对应的执行规则**。

## 工作流程

### 1. 读取用户输入

从用户当前输入的文本中提取信号，不读任何文件、不探测目录、不翻历史。

### 2. 判定意图模糊度等级

仅凭用户话语的自然语言特征判断：

| 等级 | 信号特征 | 示例 |
|------|---------|------|
| **LOW** | 包含具体对象名（模块/类/功能名） | "给用户模块新增一个导出功能" |
| | 动作词明确（新增/修改/删除/重构） | "把订单列表的分页改成分批加载" |
| | 句式完整：主语 + 动作 + 对象 | "在已有的审批流上加一个撤回按钮" |
| | 用户已自行给出边界描述 | |
| **HIGH** | 只有抽象概念，无具体对象 | "我想做一个数据分析平台" |
| | 动作词模糊（看看/能不能/搞个） | "能不能搞个自动化的东西" |
| | 用户自己也不确定要什么 | "有没有办法让流程更智能一点" |
| | 句式不完整或纯名词堆砌 | "就类似那个XX一样的" |

> 无法明确判定时，默认走 HIGH（多问比漏问安全）。

### 3. 路由

判定后，按对应的执行规范执行：

```
LOW  →  读取同目录下的 LOW.md，按该文档的规则执行
HIGH →  读取同目录下的 HIGH.md，按该文档的规则执行
```

### 4. 产出物

无论哪条分支，最终产出统一写入 `.cdd/01-requirements.md`，格式见 [OUTPUT-FORMAT.md](./OUTPUT-FORMAT.md)。

完成后告知用户当前分支选择及进入哪个阶段。
