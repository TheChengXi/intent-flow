# 需求分析文档输出格式

```markdown
# 需求文档：[项目/功能名称]

## 项目意图
[一句话描述核心目标]

## 用户群体
[目标用户是谁]

## 功能清单
1. **[功能1]**：[一句话描述]
（列出所有识别到的功能，不做核心/非核心区分）

## 核心功能

### 核心功能1：[功能名称]
- **能力**：系统能够 + [动词] + [业务对象] + [关键约束]
- **业务价值**：[直接产生的业务成果]

### 核心功能2：[功能名称]
- **能力**：...
- **业务价值**：...
（最多 3 个核心功能，超出标记为扩展）

## 业务规则

### [规则名称]
- **场景**：[什么情况下触发]
- **行为**：[系统如何响应]
- **异常处理**：[异常情况怎么处理]

## 核心功能关系矩阵

| 维度 | 涉及功能 | 说明 |
|------|---------|------|
| **依赖** | A → B | [A 需要 B 的什么输出] |
| **约束** | A ↛ B | [A 的规则如何限制 B] |
| **复用** | A ↔ B | [两者共享什么逻辑或数据] |
| **冲突** | A ⚡ B | [两者目标冲突吗？怎么调和] |

## 验证场景

### 场景1：[场景名称]
**流程**：[用户操作 → 系统响应 → 结果]
**涉及功能**：[哪些核心功能参与了]
**验证通过条件**：[场景走通的标准]

## 非功能需求（如提到则记录）
- **性能要求**：[响应时间 / 并发量]
- **安全要求**：[认证 / 授权]
- **可用性要求**：[易用性]

## 可选：范围压缩线

*（以下仅在范围决策时输出）*

**必保项**：
- [缺少就转不动的功能和连接]

**可延后**：
- [延后项及延后理由]
```
