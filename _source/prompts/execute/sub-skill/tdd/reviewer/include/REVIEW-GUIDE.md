## Severity 定义

- **Critical**: 功能错误、安全性问题、违反契约 — 必须修复
- **Important**: 可维护性、性能、代码异味 — 建议修复
- **Minor**: 命名、格式、注释 — 可修可不修

## Spec Compliance 检查清单

- [ ] 测试覆盖了 @intent 描述的所有行为
- [ ] 实现通过了所有测试
- [ ] 没有未测试的额外功能（YAGNI）
- [ ] 测试测的是行为，不是实现细节
- [ ] 接口签名与设计文档一致
- [ ] 类型安全：确认当前文件无新增编译时类型错误

## Code Quality 检查清单

- [ ] 实现是最少代码（无冗余）
- [ ] 方法长度合理（建议不超过 30 行）
- [ ] 无重复代码
- [ ] 错误处理合理
- [ ] 命名清晰
- [ ] 注释只解释"为什么"，不解释"是什么"
