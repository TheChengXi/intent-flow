# 数据层设计文档输出格式

当所有数据模型设计完成后，按照以下格式输出设计文档：

```markdown
# 数据层设计文档：[项目名称]

## 数据实体

### [实体名称1]
**用途**：[这个实体的作用]

**字段**：
- `id`: `string` - 唯一标识（必填）
- `fieldName`: `type` - [字段说明]（必填/可选）
- ...

**验证规则**：
- `fieldName`: [验证规则描述]
- ...

**关系**：
- 与 [实体2] 的关系：[一对一/一对多/多对多]
- 关系说明：[关系的业务含义]

### [实体名称2]
...

## 数据仓库

### [实体名称1]Repository
**职责**：管理 [实体名称1] 的数据持久化

**接口**：
- `create(entity: Entity1): Promise<Entity1>` - 创建实体
- `findById(id: string): Promise<Entity1 | null>` - 根据 ID 查询
- `findAll(): Promise<Entity1[]>` - 查询所有
- `update(id: string, entity: Partial<Entity1>): Promise<Entity1>` - 更新实体
- `delete(id: string): Promise<void>` - 删除实体
- [自定义查询方法]

**存储方式**：[文件系统/数据库/内存/LocalStorage等]

### [实体名称2]Repository
...

## 数据服务

### [服务名称1]Service
**职责**：[服务的职责描述]

**接口**：
- `methodName(params): ReturnType` - [方法说明]
- ...

**依赖**：
- [依赖的仓库或其他服务]

### [服务名称2]Service
...

## 数据流向

### 创建流程
[描述数据创建的流程]

### 查询流程
[描述数据查询的流程]

### 更新流程
[描述数据更新的流程]

### 删除流程
[描述数据删除的流程]

## 数据验证

### 实体级验证
[描述实体级别的验证规则]

### 业务级验证
[描述业务级别的验证规则]

## 错误处理

### 数据不存在
[如何处理数据不存在的情况]

### 数据冲突
[如何处理数据冲突的情况]

### 验证失败
[如何处理验证失败的情况]

## 性能优化

### 缓存策略
[是否需要缓存？缓存什么数据？]

### 索引设计
[如果使用数据库，需要哪些索引？]

### 批量操作
[是否需要批量操作接口？]
```
