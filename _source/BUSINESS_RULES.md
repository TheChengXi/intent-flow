# BUSINESS_RULES.md

## 用户流程

### 流程 1：编译注释生成代码
**触发条件：** 用户右键选中包含 CDD 注释的函数，选择"CDD: 编译注释"
**前置条件：** 
- 选中区域包含至少一个 @contract
- 项目根目录存在 _source/ 目录

**正常路径：**
1. 解析选中区域的注释（@contract、@step、@boundary）
2. 读取 _source/COMPILE_SPEC.md（如存在）
3. 调用 Claude API，传入注释 + 编译规范
4. 在原注释下方生成代码，末尾添加 // @end
5. 在 WorkSchedule.md 追加编译记录（时间、函数名、依赖契约版本）
6. 自动触发审查员审查

**异常处理：**
| 场景 | 系统表现 | 用户提示 |
|------|----------|----------|
| 未找到 @contract | 中止操作 | "未找到 @contract，无法编译" |
| API 调用失败 | 重试 1 次，仍失败则中止 | "API 调用失败：[错误信息]" |
| 生成代码超过 200 行 | 暂停，等待用户确认 | "预计生成 [N] 行代码，建议拆分函数。继续/取消？" |
| _source/ 不存在 | 提示初始化 | "项目未初始化，是否创建 CDD 项目结构？" |

---

### 流程 2：审查代码一致性
**触发条件：** 用户右键选中函数，选择"CDD: 审查代码"，或编译完成后自动触发
**前置条件：** 
- 选中区域包含 @contract 和 // @end 之间的完整代码块

**正常路径：**
1. 提取注释（@contract、@step、@boundary）
2. 提取代码（// @end 之前的部分）
3. 读取 _source/COMPILE_SPEC.md（如存在）
4. 调用 Claude API，传入注释 + 代码 + 审查维度
5. 生成 REVIEW_REPORT.md，追加本次审查结果
6. 在编辑器中高亮显示不一致的行（如有）
7. 在 WorkSchedule.md 追加审查记录

**审查维度（BR-001）：**
- ✅ @contract 匹配：函数签名、返回类型、异常类型
- ✅ @step 一致性：每个 @step 在代码中有对应实现（@simple 跳过）
- ✅ @boundary 处理：边界条件的 if/throw 逻辑
- ✅ 多余行为：代码中存在但注释未提及的逻辑
- ✅ COMPILE_SPEC 合规：命名、格式、平台规则
- ✅ @end 完整性：是否存在且位置正确

**审查结论（BR-002）：**
- ✅ 通过：注释与代码一致，进入下一流程
- ⚠️ 轻微偏离：非关键路径偏离，记录但不阻塞
- ❌ 严重违规：关键路径不一致，必须重新编译

**异常处理：**
| 场景 | 系统表现 | 用户提示 |
|------|----------|----------|
| 未找到 @contract 或 // @end | 中止操作 | "代码块不完整，无法审查" |
| 注释≠代码（严重） | 输出裁决选项 | "发现不一致。路径A：重新编译；路径B：代码反向同步注释。请选择。" |
| API 调用失败 | 重试 1 次，仍失败则中止 | "API 调用失败：[错误信息]" |

---

### 流程 3：存量代码转译为注释
**触发条件：** 用户右键选中代码块，选择"CDD: 转译为注释"
**前置条件：** 选中区域为有效的函数或类

**正常路径：**
1. 提取选中代码
2. 调用 Claude API，要求逆向生成 @contract、@step、@boundary
3. 在代码上方插入生成的注释
4. 在 WorkSchedule.md 追加转译记录
5. 提示用户："注释已生成，请人工审查后再编译"

**异常处理：**
| 场景 | 系统表现 | 用户提示 |
|------|----------|----------|
| 代码逻辑混乱 | 暂停，输出问题描述 | "代码逻辑不清晰：[问题]。建议人工梳理后再转译。" |
| API 调用失败 | 重试 1 次，仍失败则中止 | "API 调用失败：[错误信息]" |

---

### 流程 4：分析变更影响
**触发条件：** 用户执行命令"CDD: 分析变更影响"
**前置条件：** 项目存在 WorkSchedule.md 和 CHANGELOG.md

**正常路径：**
1. 读取 CHANGELOG.md 最新条目
2. 扫描 WorkSchedule.md，找出依赖已变更契约的编译记录
3. 输出影响分析报告：
   - 受影响的函数列表
   - 建议重新编译的优先级
   - 是否需要召集 Council（检测到 [PARADIGM SHIFT]）
4. 在 WorkSchedule.md 追加分析记录

**异常处理：**
| 场景 | 系统表现 | 用户提示 |
|------|----------|----------|
| CHANGELOG.md 不存在 | 创建空文件 | "CHANGELOG.md 已创建，请手动添加变更记录" |
| WorkSchedule.md 不存在 | 创建空文件 | "WorkSchedule.md 已创建" |

---

### 流程 5：初始化 CDD 项目
**触发条件：** 用户执行命令"CDD: 初始化项目"
**前置条件：** 无

**正常路径：**
1. 在项目根目录创建 _source/ 目录
2. 创建以下文件模板：
   - _source/PROJECT_SOUL.md
   - _source/BUSINESS_RULES.md
   - _source/TECH_STACK.md
   - _source/CONTRACTS.md
   - _source/COMPILE_SPEC.md
   - _source/CHANGELOG.md
   - WorkSchedule.md
3. 提示用户："CDD 项目结构已创建，请填写 PROJECT_SOUL.md"

**异常处理：**
| 场景 | 系统表现 | 用户提示 |
|------|----------|----------|
| _source/ 已存在 | 跳过创建，仅创建缺失文件 | "检测到已有 CDD 结构，已补充缺失文件" |

## 规则条款

### BR-001：审查维度定义
审查员必须检查以下 6 个维度（详见流程 2）。

### BR-002：审查结论分级
- ✅ 通过：所有维度无问题
- ⚠️ 轻微偏离：仅 @simple 标记的步骤或非关键路径有偏离
- ❌ 严重违规：@contract 不匹配、关键 @step 缺失、@boundary 未处理

### BR-003：编译器行为约束
- 编译器生成代码后必须添加 // @end
- 编译器不得修改注释
- 编译器预估代码超过 200 行时必须暂停

### BR-004：WorkSchedule 记录格式
每条记录格式：`日期 | 时间 | 执行角色 | 工作简述 | 耗时 | 依赖契约版本`
示例：`2026-05-09 | 14:32 | 编译器 | 编译 getUserProfile | 12s | @contract:getUserProfile:v1.0`

### BR-005：CHANGELOG 记录格式
每条记录格式：`日期 | 文件 | 变更内容 | 变更原因 | 类型`
类型：[HOTFIX] / [PARADIGM SHIFT] / [ITERATION] / [BACKTRACK]

### BR-006：API 调用重试策略
所有 API 调用失败后重试 1 次，间隔 2 秒。仍失败则向用户报错，不静默失败。

### BR-007：注释格式强制要求
- @contract 必须包含：函数名、参数类型、返回类型
- @step 必须以"[意图]"开头，关键路径禁止模糊词
- @boundary 必须以"当...时，应..."格式
- // @end 必须独占一行

### BR-008：裁决路径触发条件
当审查员发现注释≠代码且为严重违规时，必须输出：
```
发现不一致：[具体描述]
路径A（注释为准）：重新编译
路径B（代码为准）：激活代码转译员·守护模式，代码反向同步注释
请选择：A / B
```

### BR-009：回溯请求格式
当编译器、审查员发现注释无法执行时，输出：
```
《回溯请求》
问题：[具体问题]
描述：[详细说明]
建议方向：[可选的修正方向]
发送至：转译员
```

### BR-010：文件路径约定
- 核心文档：_source/*.md
- 工作日志：WorkSchedule.md（根目录）
- 变更日志：_source/CHANGELOG.md
- 审查报告：REVIEW_REPORT.md（根目录）
