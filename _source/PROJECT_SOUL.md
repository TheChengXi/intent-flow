# PROJECT_SOUL.md

## 项目愿景

CDD Validator 是一个 VSCode/IDE 插件，用于验证项目是否符合 Comment-Driven Development (CDD) v2.4.1 范式规范。它通过调用 Claude API 实现核心角色的自动化，帮助开发团队在日常工作中落地 CDD 方法论。

## 核心价值主张

**为谁：** 采用 CDD 范式的开发团队
**解决什么问题：** 手动执行 CDD 流程繁琐、容易遗漏步骤、注释与代码不一致难以发现
**如何解决：** 提供自动化的验证、编译、审查工具，集成在 IDE 中，右键即用

## 项目边界

### 包含（MVP）
- ✅ 注释格式验证（@contract、@step、@boundary）
- ✅ 注释→代码编译（调用 Claude API）
- ✅ 代码审查（以注释为标尺）
- ✅ 存量代码→注释转译
- ✅ 变更影响分析（迭代规划师）
- ✅ 右键菜单 + 命令面板交互
- ✅ 本地文件系统存储（_source/、WorkSchedule.md、CHANGELOG.md）

### 不包含（MVP）
- ❌ UI 设计师、ViewModel 架构师等前端专用角色
- ❌ 测试策略师、部署顾问
- ❌ 对话面板（后续迭代）
- ❌ 实时协作功能
- ❌ 云端同步

### 技术约束
- 必须兼容 VSCode Extension API
- 必须支持 TypeScript 项目（MVP）
- 必须离线可用（除 API 调用外）
- 响应时间：编译单个函数 < 30s，审查 < 10s

## 成功标准

**MVP 验收标准：**
1. 用户可以右键选中函数，选择"CDD: 编译注释"，生成符合注释的代码
2. 用户可以右键选中函数，选择"CDD: 审查代码"，输出审查报告
3. 用户可以右键选中代码块，选择"CDD: 转译为注释"，生成 CDD 格式注释
4. 用户可以执行"CDD: 分析变更影响"，查看哪些模块需要重新编译
5. 所有操作记录自动追加到 WorkSchedule.md

**质量标准：**
- 编译器生成的代码必须通过审查员审查（一致性 > 95%）
- 审查员必须能识别注释与代码的不一致（准确率 > 90%）
- 插件不得阻塞 IDE 主线程（所有 API 调用异步）

## 非功能性需求

- **可维护性：** 代码本身遵循 CDD 范式（自举）
- **可扩展性：** 角色系统模块化，后续可轻松添加新角色
- **安全性：** API Key 存储在 VSCode Secret Storage
- **性能：** 单次 API 调用失败不影响其他功能
